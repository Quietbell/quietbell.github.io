A daily Jira digest in Google Chat

Updated 20 November 2026 · 4 min read

Most teams do not need to see every Jira update in Google Chat. They need one message a day that answers one question: what should we look at this morning? A digest does that. Here are the JQL queries that work, and two ways to send them.

Six digests that teams actually read

DigestJQLWhen
Open bugsproject = OPS AND issuetype = Bug AND statusCategory != Done ORDER BY priority DESCEvery weekday 9:00
Due today or tomorrowproject = OPS AND due <= endOfDay(1d) AND statusCategory != DoneEvery weekday 8:30
Overdueproject = OPS AND due < startOfDay() AND statusCategory != Done ORDER BY due ASCMonday 9:00
Blocked for a weekproject = OPS AND status = Blocked AND status CHANGED TO Blocked BEFORE -7dMonday and Thursday
Unassignedproject = OPS AND assignee IS EMPTY AND statusCategory != Done AND created < -1dEvery weekday
Critical and highestproject = OPS AND priority in (Highest, Critical) AND statusCategory != DoneTwice a day

Test each query in Jira's issue search first. A digest built on a JQL that returns 400 issues is noise again: add ORDER BY and keep the list under 25.

Way 1: Jira Automation on a schedule (free)

  1. Project settings → Automation → Create rule, trigger Scheduled. Tick Run a JQL search and paste your query.
  2. Action Send web request to your Google Chat webhook, method POST, custom data:
{
  "text": "*Open bugs · {{now.format(\"EEE d MMM\")}}*\n{{#issues}}• {{key}} {{summary.jsonEncode}} — {{status.name}}{{^last}}\n{{/}}{{/}}"
}

What to know: the rule runs once for the whole list (good for the Automation quota), but the message is plain text, there is no grouping by status, and when the search returns nothing you get an empty message unless you add a condition on {{issues.size}}.

Way 2: a digest in Threadbell

Threadbell has a Digests tab made for this:

  • Pick a template (the six above are built in) or paste your own JQL; the query is validated against Jira before saving.
  • Choose days, hour and time zone. One message, grouped by status, with priority and assignee, capped at 10, 25 or 50 issues, with the count of the rest.
  • Nothing is sent when the search is empty (or a one-line "all clear", your choice).
  • Send now to test without waiting for tomorrow.
  • Every digest appears in the delivery log with its result.

Digest or live notifications?

Both, but not in the same space. Live notifications belong where the work happens (a space per team, one thread per issue). Digests belong where decisions are made (a leads space, a support space at the start of the shift). A team that mixes them ends up muting the space.

Sprint and release announcements in Google Chat

Updated 20 November 2026 · 3 min read

Issue notifications are for the people doing the work. Sprint and release events are for everyone else: product, support, sales. Three events are worth a message in a wider Google Chat space.

The three events

EventWhat the message should say
Sprint startedSprint name, goal, start and end dates, link to the board
Sprint completedSprint name, dates, link to the board (the report is one click away)
Version releasedVersion name, release date, link to the version page with the issue list

With Jira Automation

Jira Automation has triggers for Sprint created / started / completed and Version created / updated / released. Pair them with Send web request to a Google Chat webhook:

{
  "text": "🏁 *Sprint started: {{sprint.name}}*\n{{sprint.goal}}\n{{sprint.startDate.shortDate}} → {{sprint.endDate.shortDate}}"
}

Works well. Two limits: the goal is not JSON-escaped (use {{sprint.goal.jsonEncode}}), and there is no link to the board unless you hard-code it.

With Threadbell

In Threadbell, tick Team events in a rule: sprint started, sprint completed, version released. Messages are cards with the goal, the dates, the project and an Open in Jira button, in the language of the space (English, French, German, Spanish, Portuguese). The template Sprints and releases creates a rule with only these three events, for a company-wide space.

Sprint events need Jira Software (a Scrum board). Version events work in any Jira project with releases. Threadbell needs no additional permission for either.

Where to post them

  • #product-updates or #general: version released only.
  • #team-xyz: sprint started and completed, next to the issue thread notifications.
  • Avoid the on-call space: these are not alerts.

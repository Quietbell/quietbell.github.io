How to send Jira notifications to Google Chat

Updated 18 November 2026 · 6 min read

Google Chat has no built-in Jira connection, but there are three reliable ways to get Jira updates into a space. All three start with the same step: an incoming webhook in Google Chat.

Step 0: create a Google Chat webhook

  1. Open Google Chat in a browser (webhooks can't be set up from the mobile app) and open the space that should receive the updates.
  2. Click the arrow next to the space name, then Apps & integrations.
  3. Click Add webhooks, give it a name such as "Jira" and click Save.
  4. Click More next to the webhook, then Copy link. The URL starts with https://chat.googleapis.com/v1/spaces/ and contains a secret token: treat it like a password, anyone with it can post in the space.

Webhooks need a Business or Enterprise Google Workspace account, and your organization must allow them. If you don't see the option, ask your Workspace admin to check Apps → Google Workspace → Google Chat → Chat apps in the Admin console, setting "Allow users to add and use incoming webhooks".

Option 1: Jira Automation (free, do it yourself)

Good for one or two simple alerts. In your Jira project:

  1. Open Project settings → Automation → Create rule.
  2. Pick a trigger, for example Work item transitioned or Work item created. Add conditions if you need them.
  3. Add the action Send web request: paste the webhook URL, method POST, header Content-Type: application/json; charset=UTF-8, body Custom data:
{
  "text": "*{{issue.key}}* {{issue.summary.jsonEncode}}\nStatus: {{issue.status.name}} · by {{initiator.displayName}}\n<{{issue.url}}|Open in Jira>"
}

Limits to know: each run counts toward your monthly Automation quota, every rule is one event for one space, messages don't group by issue, and failures only show in the rule's audit log.

Option 2: Google's "Google Chat for Jira Cloud" app

Free, published by Google on the Atlassian Marketplace. It is the most installed option. Read its recent reviews before you choose: on 18 November 2026 it was rated 2.30 out of 5 from 109 reviews, and several reviews mention setup problems.

Option 3: a dedicated app (Threadbell)

Threadbell is built for teams that want only the updates that matter, in a readable form:

  • Rules per space: pick events, projects, issue types, priorities, from/to status, or any JQL.
  • One thread per issue, so follow-ups stay together.
  • Daily digests (for example "open bugs at 9:00") and personal alerts when someone is assigned or mentioned.
  • A delivery log that explains every failure, and automatic retries.
  • Runs on Atlassian Forge and talks only to the Google Chat API. Free for up to 10 users.

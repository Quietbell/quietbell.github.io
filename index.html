Threadbell: Google Chat notifications for Jira

Threadbell sends Jira issue updates to Google Chat spaces. You decide which events, from which issues, go to which space.

Set up your first rule

  1. In Google Chat, open the space, then Apps & integrations → Webhooks → Add webhook. Give it a name and copy the URL. Incoming webhooks need a Google Workspace account.
  2. In Jira, open Apps → Manage apps → Google Chat notifications (Jira admins), or Project settings → Google Chat (project admins).
  3. Select Add rule, give it a name and paste the webhook URL.
  4. Select Send a test message. A sample card should appear in the space.
  5. Choose the events and filters, then save.

Events

EventSent when
CreatedAn issue is created.
Status changedAn issue moves to another status. You can limit this to chosen "from" and "to" statuses.
ResolvedAn issue gets a resolution.
AssignedThe assignee changes.
Priority changedThe priority changes.
CommentedA comment is added.
UpdatedOther fields change. Ranking and time tracking changes are ignored.
DeletedAn issue is deleted.

Filters

  • Projects: one, several or all (admin page). A rule made in project settings covers that project.
  • Issue types and priorities.
  • JQL: any query, for example labels = customer AND priority in (Highest, High). The query is checked when you save.
  • Ignore Jira Automation: skips changes made by automation rules.

Message options

  • Card (issue header, what changed, chosen fields, Open button) or compact (one line of text).
  • One thread per issue: follow-ups for the same issue go in the same thread.
  • Mention @all for the priorities you choose.
  • Include description when an issue is created.

Daily digests

Open the Digests tab to send one summary a day to a space: choose the projects (or a JQL filter limited to them), the days, the hour in your time zone and how to group the issues (status, assignee, priority or none). An empty digest is not sent. Project admins manage digests for their own project.

Personal alerts

Each person can open My Google Chat alerts (Apps menu in Jira), paste a webhook of their own space or direct-message space and choose: assigned to me, mentioned, comments and status changes on my issues, and issues I watch. Threadbell checks with Jira that the person can open the issue before sending anything. Your own changes never alert you. A site admin can turn personal alerts off in the Personal alerts tab.

Delivery log and troubleshooting

The Delivery log tab lists the latest messages and the reason for any failure.

MessageWhat to do
Webhook not foundThe webhook or the space was deleted. Create a new webhook and update the rule.
Webhook refusedThe URL is incomplete or the space no longer allows webhooks. Copy the URL again.
Rate limitedGoogle Chat accepts about one message per second per space. Threadbell retries automatically.
Nothing arrivesCheck that the rule is on, then check its filters against the issue. A change made by the app's own account is never sent.

Data and security

Threadbell runs on Atlassian Forge. It stores your rules and digests, the webhook URLs (as encrypted secrets), the settings of people who turned on personal alerts (account ID, space, chosen alerts) and a delivery log of up to 300 entries kept 30 days. It sends messages only to chat.googleapis.com. See the privacy policy.

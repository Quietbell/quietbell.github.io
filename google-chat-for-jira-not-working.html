Jira notifications not arriving in Google Chat? A checklist

Updated 18 November 2026

Work through these checks in order. Most problems come from the webhook or from Google Workspace settings, not from Jira.

1. Is it the right kind of Google account?

Incoming webhooks need a Business or Enterprise Google Workspace account. They can't be set up from a personal Gmail account, nor from the Chat mobile app: use Chat in a browser.

2. Does your Workspace allow webhooks and Chat apps?

Your Workspace admin controls this in the Admin console under Apps → Google Workspace → Google Chat → Chat apps: the setting "Allow users to add and use incoming webhooks" must be on, and Chat apps must be allowed for your team. If the option is missing for everyone in your company, ask your admin.

3. Does the webhook still exist?

If someone removed the webhook from the space, or deleted the space, messages can't be delivered anymore. Create a new webhook in the space and paste the new URL wherever Jira uses it.

4. Read the error code

CodeWhat it usually meansWhat to do
400Google refused the request: for example "API key not valid" when the URL was cut off, or a message body it can't read.Copy the full webhook URL again, including key and token. If you build the JSON yourself, escape quotes and line breaks.
401 / 403The webhook isn't allowed to post, for example after webhooks were turned off for your organization.Copy the URL again, then check the Workspace settings above.
404The webhook or the space no longer exists.Create a new webhook.
429Too many messages: Google allows about one request per second per space, shared by all webhooks in that space.Slow down or retry later. Bulk edits in Jira often hit this.
5xxGoogle Chat is temporarily unavailable.Retry a little later.

5. Does the rule match the issue?

Check the project, issue type, status and JQL filters against the issue you changed. Changes made by an app's own account, or by Jira Automation when you chose to ignore it, are often skipped on purpose.

6. Restricted comments

Comments limited to a role or a group, and internal notes in Jira Service Management, should never be posted to a chat space. A good integration skips them silently.

Still stuck with the app you use?

If you use Google's "Google Chat for Jira Cloud" app, check its listing and support page first. If you need clear error messages, Threadbell shows each delivery and the reason for any failure in plain words, with automatic retries.

Jira Automation to Google Chat: a card template that works

Updated 20 November 2026 · 5 min read

The free way to post Jira updates in Google Chat is a Jira Automation rule with the Send web request action. It works, but most copies you find online post plain text, break on a quote in the issue summary, or create a new message for every update. This page gives you a card that holds, and explains the three traps.

What you need

  • A Google Chat incoming webhook URL for the space (how to create one: step 0 of this guide).
  • Project admin rights in Jira, to create an Automation rule.

The rule

  1. Project settings → Automation → Create rule.
  2. Trigger: Work item transitioned (or Work item created; one rule per trigger).
  3. Action: Send web request. Web request URL: paste the webhook URL and add &threadKey={{issue.key}}&messageReplyOption=REPLY_MESSAGE_FALLBACK_TO_NEW_THREAD at the end. HTTP method POST. Web request body: Custom data.

Paste this as the custom data:

{
  "cardsV2": [{
    "cardId": "{{issue.key}}",
    "card": {
      "header": {
        "title": "{{issue.key}} · {{issue.summary.jsonEncode}}",
        "subtitle": "{{issue.issueType.name}} · {{project.name}} · {{issue.priority.name}}"
      },
      "sections": [{
        "widgets": [
          { "decoratedText": { "topLabel": "Status", "text": "{{issue.status.name}}" } },
          { "decoratedText": { "topLabel": "Assignee", "text": "{{issue.assignee.displayName.jsonEncode}}" } },
          { "decoratedText": { "topLabel": "Changed by", "text": "{{initiator.displayName.jsonEncode}}" } },
          { "buttonList": { "buttons": [
            { "text": "Open {{issue.key}}", "onClick": { "openLink": { "url": "{{issue.url}}" } } }
          ] } }
        ]
      }]
    }
  }]
}

Leave the Headers section empty unless Jira asks for one. If you add a header, use Content-Type: application/json; charset=UTF-8.

The three traps

1. A quote in the summary breaks the JSON

An issue called Fix "Pay now" button produces invalid JSON and Google answers 400. Every text that a person typed must go through .jsonEncode: {{issue.summary.jsonEncode}}, {{issue.assignee.displayName.jsonEncode}}, {{comment.body.jsonEncode}}. Field names chosen from a list (status, priority, issue type) are safe.

2. Every update is a new message

Without the threadKey parameter in the URL, each run posts a new top-level message, and the space fills up. With threadKey={{issue.key}} and messageReplyOption=REPLY_MESSAGE_FALLBACK_TO_NEW_THREAD, all updates of one issue land in the same thread. This only works in spaces with threaded replies enabled (the default for new spaces).

3. Empty fields

An unassigned issue gives an empty text and Google rejects the widget. Either accept the risk, or replace the assignee line with "text": "{{#if(exists(issue.assignee))}}{{issue.assignee.displayName.jsonEncode}}{{/}}{{#if(not(exists(issue.assignee)))}}Unassigned{{/}}".

Limits you will hit

  • Automation quota: each run counts toward the monthly limit of your plan. Ten rules on a busy project can use it up in a week.
  • One rule, one space, one event: four events for two spaces means eight rules to maintain.
  • No retries: if Google answers 429 or 503, the message is lost. The only trace is the rule's audit log.
  • Restricted comments are sent like any other comment. Jira Service Management internal notes too. Add a condition if your rule posts comments.
  • Mentions: a summary containing <users/all> would ping the whole space. Rare, but real.

When a dedicated app is worth it

If you need several projects, filters per space, one thread per issue without URL tricks, daily digests, quiet hours or personal alerts, an app does it from one screen and keeps a delivery log. Threadbell is built for that, and stays free for up to 10 users. The Automation rule above is the right choice for one simple alert.
